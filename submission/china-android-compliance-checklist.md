# 2048 Solo 中国安卓市场合规检查清单

最后更新日期：2026-04-10

本文档用于核对 `2048 Solo` 当前版本在中国安卓市场上架前的关键合规项。

---

## 1. 主体与基础资质

### 必备

- [ ] 上架主体已确定（公司 / 个体工商户）
- [ ] 主体名称与开发者后台信息一致
- [ ] 营业执照可用于平台认证
- [ ] 开发者联系人、邮箱、手机号可正常接收审核通知

### 强烈建议准备

- [ ] 软件著作权（App 或游戏软著）
- [ ] 商标/品牌证明（如使用品牌名推广）

---

## 2. 游戏属性判断

当前应用属于：

- 数字合成玩法
- 单机离线
- 无联网对战
- 无聊天社区
- 无账号体系
- 无充值

### 当前建议判断

从玩法表现看，通常会被归入 **游戏类产品**，而不是普通工具/教育类应用。

因此建议在正式上架前确认：

- [ ] 目标市场是否将本产品按“游戏”类审核
- [ ] 若按“游戏”审核，是否要求提供版号/联运/游戏资质
- [ ] 是否考虑先以测试版/展示版投放到对单机轻游戏更友好的渠道

---

## 3. 版号与软著

### 高风险提醒

如果目标市场将应用识别为“游戏”，则可能要求：

- [ ] 游戏版号
- [ ] 游戏软著
- [ ] 相关授权文件

### 当前版本状态

- [ ] 尚未确认是否具备版号
- [ ] 尚未确认是否具备软著

### 建议

- [ ] 上架前逐个确认目标市场要求
- [ ] 如果没有版号，优先评估可接受的投放渠道或测试渠道
- [ ] 如果计划长期运营，尽快准备软著与版号路径

---

## 4. 隐私合规

### 当前版本已具备

- [x] 离线单机可玩
- [x] 不依赖自建服务端
- [x] 不强制登录
- [x] 本地保存设置与进度

### 当前版本仍建议补齐

- [ ] 首次启动隐私政策弹窗
- [ ] 明确的“同意 / 不同意”路径
- [ ] 应用内长期可访问的隐私政策入口
- [ ] 真实开发者信息与联系方式
- [ ] 若使用第三方 SDK，逐项列明 SDK 名称、用途、隐私链接

### 正式上架前必须核对

- [ ] 隐私政策已单独成文
- [ ] 隐私政策已托管为公网可访问链接
- [ ] 文本与实际行为一致
- [ ] 未夸大“零收集”或“完全不处理数据”

---

## 5. 权限与设备能力

### 当前建议口径

本版本应尽量保持：

- [x] 不主动申请无关权限
- [x] 不申请通讯录/定位/短信/相机/麦克风等敏感权限

### 上架前检查

- [ ] 清点最终 APK / AAB 实际权限
- [ ] 检查是否存在 SDK 自动带入权限
- [ ] 权限说明与市场后台填写一致

---

## 6. 广告、支付与第三方 SDK

### 当前版本状态

- [x] 当前未接入广告
- [x] 当前未接入内购
- [x] 当前未接入登录 SDK
- [x] 当前未接入统计 SDK

### 如果后续接入

一旦接入以下能力，需要同步更新：

- 隐私政策
- 市场后台 SDK 声明
- 合规说明
- 审核备注

待同步的能力包括：

- [ ] 广告 SDK
- [ ] 支付 SDK
- [ ] 统计/埋点 SDK
- [ ] 崩溃分析 SDK
- [ ] 推送 SDK

---

## 7. 内容审核

当前版本内容相对安全，主要为：

- 数字方块
- 高分挑战
- 成就展示
- 本地设置

### 一般应避免

- [ ] 涉赌/抽奖/现金收益暗示
- [ ] 虚假福利文案
- [ ] 夸张诱导点击文案
- [ ] 涉政、暴力、低俗、迷信等违规内容

---

## 8. 当前版本离正式上架还差什么

基于当前仓库状态，最值得优先补的不是玩法，而是合规和发布基础设施：

### 必补

1. [ ] 首次启动隐私政策弹窗
2. [ ] 应用内隐私政策入口
3. [ ] 开发者信息与支持方式
4. [ ] 正式签名配置
5. [ ] 正式版本号与包名策略

### 强烈建议

6. [ ] 软件著作权准备
7. [ ] 目标市场版号要求逐项确认
8. [ ] 真机截图替换宣传图
9. [ ] 渠道后台填写信息统一

---

## 9. 建议优先执行顺序

1. 先补隐私弹窗和隐私入口
2. 再确认主体、软著、版号路径
3. 再准备正式签名与版本号
4. 最后按各市场后台提审
